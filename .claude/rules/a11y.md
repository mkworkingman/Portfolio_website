# Accessibility (WCAG 2.2 AA)

- **Native elements first.** `<button>`, `<a href>`, `<input>` and `<dialog>` come with focus, keyboard behaviour, role and state. ARIA only when no native element fits.
- **Every control has an accessible name** in every language: visible text, or `data-i18n-label` (becomes `aria-label`) for icon-only controls. Ship the English text in the HTML so names exist even if the script fails.
- **State lives in ARIA, not only in classes.** Pair `is-open` and the like with `aria-expanded`, `aria-current`, `aria-pressed` or `aria-selected`.
- **Colour is never the only signal (1.4.1).** "Current" or "error" needs a second cue: text, an icon, an underline or a border-thickness change.
- **Contrast:** 4.5:1 body text, 3:1 for large text (≥24px, or ≥19px bold), 3:1 for UI component boundaries and focus indicators.
- **Focus:** never remove the global `:focus-visible` ring without a replacement, and keep it unobscured by the sticky header (2.4.11).
- **Targets** at least 24×24 CSS px (2.5.8).
- **Headings are an outline:** one `<h1>`, no skipped levels, size through CSS. Label each `<section>` with `aria-labelledby`.
- **Decorative visuals** (the hero canvas, icons next to text) get `aria-hidden="true"`. Never put it on anything focusable.
- **Motion:** anything that moves respects `prefers-reduced-motion`.
- **Language:** `<html lang>` follows the switcher; text in another language gets its own `lang`.
- Automated tools catch only ~30–40% of issues. After UI changes run `/ui-check` (includes axe) and the `a11y-reviewer` agent for keyboard, screen-reader and contrast-in-context checks.
